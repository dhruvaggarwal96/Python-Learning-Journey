## 🧠 Key Learnings

* CTEs improve SQL readability and maintainability.
* CTEs are ideal for breaking complex queries into smaller logical steps.
* A CTE exists only during the execution of a single SQL statement.
* Use `WHERE` to filter rows from a CTE after aggregation.
* Use `HAVING` only when filtering grouped results.
* Multiple CTEs are defined using a single `WITH` keyword and separated by commas.
* `UNION ALL` is generally faster than `UNION` because it does not remove duplicates.

---

## 💡 Interview Takeaways

* Explain when to choose a CTE instead of a subquery.
* Understand the execution flow of a CTE.
* Know the difference between `WHERE` and `HAVING`.
* Be comfortable writing multiple CTEs in a single query.
* Write clean, readable SQL instead of deeply nested subqueries.
